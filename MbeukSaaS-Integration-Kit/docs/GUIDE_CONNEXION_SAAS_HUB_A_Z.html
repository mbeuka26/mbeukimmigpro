1Principe

ComposantRôle
Hub CentralIdentité clients, licences, paiements (Chariow), commissions influenceurs
Developer PortalVotre cockpit : apps, tarifs, clé API, téléchargements kit/SDK/guides
Votre SaaSMétier + UI (ne pas reconstruire) — appelle le Hub via Edge/SDK
MbeukSaaS-Integration-KitTemplates Edge, frontend affiliate, scripts, docs pour brancher le SaaS
Parcours client officiel : Marketplace → Installer → compte dans votre SaaS → acheter/essai → licence confirmée par webhook Hub.

2Compte Developer Portal

  1. Ouvrez le Developer Portal Mbeuk et créez / activez votre compte.
  2. Complétez le profil (entreprise, contacts).
  3. Attendez l’activation si une validation admin est requise.

3Application & plans

  1. Créez une application SaaS (nom, slug, description, URL d’installation).
  2. Ajoutez au moins un produit / plan (prix, essai éventuel).
  3. Notez les UUID :
    • MBEUK_APPLICATION_ID — identité technique de l’app
    • MBEUK_PRODUCT_ID — identité commerciale / licence
Ne jamais hardcoder ces UUID dans le code public frontend. Secrets = serveur / Edge Functions uniquement.

4Clé API Hub

  1. Allez dans /sdk du portal.
  2. Générez une clé mbs_… liée à votre application.
  3. Scopes recommandés : auth:login, auth:register, licenses:read, licenses:write, checkout:write, et influencers:read si affiliation.
  4. Copiez la clé une seule fois — stockez-la dans les secrets Supabase / Vercel (jamais dans Git).

5Téléchargements (page /sdk)

  • MbeukSaaS-Integration-Kit-v1.8.0.zip — kit complet avec MbeukHubGate
  • mbeuk-hub-sdk-2.0.0.tgz — SDK npm
  • GUIDE_CONNEXION_SAAS_HUB_A_Z.html — ce document
  • PROMPT_CONNECT_SAAS_TO_HUB.md — prompt pour Cursor / agent IA

6Installer le kit

unzip MbeukSaaS-Integration-Kit-v1.8.0.zip
cd mon-saas
node chemin/kit/scripts/install/apply-kit.mjs .
# copies barrière, PWA si absente, edges manquantes — n'écrase jamais l'auth
node chemin/kit/scripts/health-check.mjs .
node chemin/kit/scripts/validate/validate.mjs .

Lisez aussi docs/HOW_TO_USE.md et templates/frontend/universal-barrier/README.md.

7Si votre projet a DÉJÀ une page d’authentification

FIX, DON’T REBUILD. Ne créez pas une nouvelle UI login/register. Branchez Hub derrière les écrans existants.
  • Conservez vos formulaires, styles, routes (/login, /auth, etc.).
  • Remplacez uniquement l’appel « auth locale » par :
    • Edge hub-auth-login / hub-auth-register, ou
    • SDK serveur hub.auth.login / register
  • Séparez connexion réussie (session) et licence active (entitlement) : un utilisateur peut se connecter sans être PRO.
  • Messages UX recommandés :
    • Email mal formé → « Email invalide… »
    • Email inconnu → « Vérifiez votre email et mot de passe. »
    • Mauvais mot de passe → « Vérifiez votre mot de passe. »

Installer la barrière universelle

Commande unique recommandée : node scripts/install/apply-kit.mjs . puis import { bootMbeukHubGate } from "./mbeuk-gate/boot.js" au bootstrap. Ajoutez <div id="hub-user-status"> dans le header existant. Si aucune auth n’existe, authMode: "universal".

Ajoutez un point de montage header pour le nom et les badges Essai gratuit / Standard. Le guide complet se trouve dans templates/frontend/universal-barrier/README.md.

8Edge Functions & secrets

  1. Copiez templates/supabase/edge-functions/ (dont hub-* et hub-validate-promo).
  2. Configurez les secrets Supabase : MBEUK_HUB_URL, MBEUK_HUB_API_KEY, MBEUK_PRODUCT_ID, MBEUK_APPLICATION_ID, MBEUK_AUTH_BRIDGE_SECRET, MBEUK_SERVICE_ROLE_KEY.
  3. Déployez avec templates/supabase/deploy-edge-functions.sh.
bash scripts/deploy-edge-functions.sh

9Paiement & licences

  1. Checkout uniquement via Hub (hub-checkout) — prix résolu côté serveur.
  2. La page « succès » du fournisseur de paiement n’est pas une preuve de licence.
  3. Après paiement : polling hub-sync-license / statut licence jusqu’à accès PRO.
  4. Webhook Chariow = sur le Hub, pas sur votre SaaS.

10Affiliation

  • Capturer ?ref= au chargement (fichier hub-affiliate.js du kit).
  • Code promo manuel optionnel ; code vide OK si link_ref présent.
  • Valider via hub-validate-promo.
  • Message invalide : « Code promo invalide. Vérifiez le code et réessayez. »

11Checklist de tests

  • ☐ Register + login (avec et sans licence)
  • ☐ Email / mot de passe incorrects → bons messages
  • ☐ Essai gratuit (si activé)
  • ☐ Achat → webhook → accès PRO (poll)
  • ☐ Code promo valide / invalide / vide + ?ref=
  • ☐ Aucun secret dans le frontend ni dans Git

12Sécurité — non négociable

  • Clé mbs_… : serveur uniquement
  • Pas de création de licence côté client après redirect
  • HTTPS partout
  • Rate-limit sur login / checkout (Edge)
  • Ne jamais coller secrets dans un chat IA

13Prompt IA

Téléchargez PROMPT_CONNECT_SAAS_TO_HUB.md + le ZIP kit, ouvrez Cursor dans votre repo SaaS, et donnez le prompt.

Si une page auth existe déjà, l’agent doit fixer le bridge Hub, pas reconstruire l’écran.
